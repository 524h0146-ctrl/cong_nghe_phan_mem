# Triển khai School trên hai nền tảng
1. Windows Docker Desktop (Linux containers, CPU x86-64): đặt biến SQL_PASSWORD bằng mật khẩu lab mạnh riêng. Trong PowerShell: $env:SQL_PASSWORD = Read-Host "SQL demo password". Chạy các lệnh README. Chờ log SQL xuất hiện "ready for client connections". Khi sqlcmd hỏi mật khẩu, nhập cùng giá trị. Khởi tạo School.sql một lần trên volume mới. Hai giao diện dùng chung dữ liệu, cổng SQL chỉ nằm trong mạng Compose.
2. Ubuntu x86-64: cài Docker Engine và Compose plugin. Sao chép source, export SQL_PASSWORD trong phiên shell, chạy lệnh Compose như trên. Kiểm tra docker compose ps và curl -I http://localhost:8081/Departments. Chỉ mở cổng web cần dùng.
3. CI/CD: đặt nội dung source ở gốc repo GitHub. Workflow images.yml build cả hai project, chỉ push GHCR khi lên main, gắn tag theo commit. Trên máy triển khai, dùng docker login ghcr.io nếu image private, docker pull theo SHA và chạy image với ConnectionStrings__School được cấp qua secrets. Đây là bước phát hành thủ công sau bước CI. Để deploy tự động qua Ubuntu, cấu hình runner self-hosted có nhãn school-deploy cho environment production theo workflow deploy.yml.
4. Azure: tạo ACR, đăng nhập az acr login --name <registry>, tag và push image MVC/Razor vào <registry>.azurecr.io. Tạo App Service for Containers, chọn image và port 8080, cấp quyền AcrPull cho managed identity. Cấu hình biến ConnectionStrings__School hướng tới Azure SQL, chạy School.sql (phần tạo bảng trên DB đích) trước khi truy cập /Departments.
5. AWS: tạo ECR repo; dùng aws ecr get-login-password --region <region> | docker login --username AWS --password-stdin <registry>. Tag và push image. Với Elastic Beanstalk Docker, triển khai Dockerrun.aws.json trỏ tới image; IAM instance profile cần quyền đọc ECR. Truyền ConnectionStrings__School bằng cấu hình môi trường cho RDS SQL Server.
6. Bài đặc biệt: mở URL HTTPS do hosting cấp, thêm và sửa một Department, tải lại bằng trình duyệt thứ hai, kiểm tra DB thật sự lưu. Lưu URL, thời gian thử, ảnh trang, log, tài nguyên đã dùng và kết quả vào báo cáo. Đối với tài nguyên cloud có phí, quyết định tạo/xóa do chủ tài khoản thực hiện.
